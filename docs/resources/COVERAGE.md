## Regenerate and review

Run from the repository root using the project's installed dependencies:

```powershell
npm run resources:validate
npm run resources:report
```

The report emits current topic, campus, audience, verification, high-impact and second-review counts, each record's ID/status/source, blocked-source attempts and validation notices. It does not certify facts or overwrite this authored checklist report. To regenerate the per-topic review columns:

```powershell
npx tsx -e "import {resources as r} from './src/data/resources'; console.table(Array.from({length:20},(_,i)=>{const topic=String(i+1).padStart(2,'0');const a=r.filter(x=>x.topic===topic);return {topic,total:a.length,reviewed:a.filter(x=>x.verification.status==='reviewed').length,partial:a.filter(x=>x.verification.status==='partial').length,secondReview:a.filter(x=>x.secondReview).length}}))"
```

For migration totals, compare current IDs with `git show 1f27e37:src/data/resources/index.ts` and its baseline `library`, `recreation`, and `deadlines` imports; apply `mergedResourceIds` from the current registry. The arithmetic above was checked this way. Revisit the four linked source matrices whenever a service or qualification changes; a newly reachable page does not automatically resolve its coverage gap. Release test/build/browser/deployment results are documented separately, not inferred from these counts.
